# 像素工具形态迁移：从单文件 HTML 到其他形态

> 采集：2026-09-09（Cielevel 指定主题「像素工具从 HTML 形态向其他形态转换的方向探索」，要求发散、全面）。
> 采集方式：5 路并行子调研（桌面框架 / Rust+WASM 多壳 / 引擎与宿主插件 / Agent 原生形态 / Web 增强与分发）+ 主 Agent 用 `gh repo view` 与官方文档逐项核验。
> 标注约定：数字后带「~」= 估算或第三方数据；「未验证」= 未找到可核验来源，宁缺毋假。
> 配套 GitHub 档案：`ShelfGithub/deepdive/deepdive-mcp-tool-shop-org-glyphstudio.md`、`ShelfGithub/deepdive/deepdive-xianfei-imagine-plus.md`；其余仓库未单独立档，链接见本文第六节。
> 相邻档案：`Shelf/ai/lightweight-injectable-pixel-tools.md`（注入形态对比）、`Shelf/game-dev/ai-pixel-art-standardization.md`（像素标准化流程）、`ShelfGithub/ecosystem/lightweight-pixel-art-tools.md`（轻量工具生态）。

## 〇、结论速览

- **形态不是二选一，而是「一个核心 + 多个外壳」**。真正要决定的是：核心算法用什么语言写、先出哪几个壳、哪些壳永远不做。
- **最小改动路线（保住现有 HTML/JS）**：Tauri 2 打包 —— 前端零重写，安装包 2–20MB，Win/macOS/Linux + iOS/Android；代价是 Linux WebKitGTK 渲染差异与 File System Access API 不可用。
- **长期最强路线（性能 + Agent + 全平台）**：Rust 核心 crate + CLI/WASM/MCP 三壳起步，再按需加 Node(napi-rs)、Python(PyO3)、Godot/Unity(GDExtension/C ABI)、移动端(UniFFI)。
- **Agent 友好度**：MCP（稳定规范 2026-07-28）+ 结构化 CLI 契约 + SKILL.md 三件套已是事实标准；**没有 headless CLI 的 GUI 应用对 Agent 基本不可用**（PixiEditor 至今无 CLI，见第六节）。
- **性能天花板**：浏览器里 WebGPU > WASM SIMD+threads > WASM > JS；但 WebGPU 覆盖不足（Firefox 仅 Windows、桌面 Safari 未默认），必须保留 WASM/CPU 回退。
- **美观化的关键不在框架，而在「自绘能力 + 设计令牌」**：egui/Slint/Flutter/Avalonia 均自绘，可做到完全一致的视觉；WebView 壳则受各平台 WebView 渲染差异影响。

## 一、约束（用户给出的四条硬指标）

1. **跨平台**：Win/macOS/Linux 必需，移动端加分。
2. **性能优秀**：像素视频逐帧处理、大图网格检测、色板量化属于 CPU 密集 + 可并行。
3. **能很好美观化**：UI 与产物（sheet.png / 预览图 / 元数据）都要好看、可定制。
4. **面向用户与 Agent 友好**：人能顺手用，Agent 能无头调用、可脚本化、可验证。

## 二、现状定位：单文件 HTML 的优势与天花板

**优势（不该轻易丢掉）**
- 零安装、双击即用，Win/macOS/Linux 一致；文本文件天然可 Git diff / 版本化 / 静态托管（GitHub Pages、Cloudflare Pages、itch.io 单 HTML 直传）。
- 现有算法（网格检测、色板量化、spritesheet 导出）已经跑通，重写成本 = 重新踩坑。

**天花板（用户想迁移的真实原因）**
- **本地文件能力受限**：File System Access API（`showOpenFilePicker` / `showSaveFilePicker` / `showDirectoryPicker`）仅 Chromium 桌面支持，Firefox 与 Safari 不支持（caniuse 全球使用率约 30.85%，采集 2026-09-09）——意味着「批量读目录、原地覆盖保存」在非 Chromium 上做不到。
- **file:// 下不能跨源隔离**：WASM threads 需要 COOP/COEP 响应头，双击打开的本地文件拿不到，线程并行只能在起本地服务器/部署后使用。
- **GPU 与并行上限**：WebGPU 在 Chrome 113+、Safari 26.0+ 可用，Firefox 141（2025-07）仅先开 Windows；`file://` 场景同样受限。
- **系统集成弱**：文件关联、拖入图标、后台批处理、托盘、右键菜单、命令行调用等桌面语义缺失。
- **Agent 调用链长**：Agent 要驱动它，通常得靠浏览器自动化（Playwright），比直接调 CLI/MCP 脆弱得多。

## 三、八类候选形态（发散清单）

### 形态 1｜桌面 WebView 壳：保住现有前端
| 方案 | 体积（采集 2026-09-09） | 跨平台 | 前端复用 | 关键代价 |
|---|---|---|---|---|
| **Tauri 2** | 安装包 macOS 2–6MB / Win 1–3MB / Linux 3–8MB，生产级 8–20MB | Win/macOS/Linux + iOS/Android | ✅ 现有 HTML/CSS/JS 零重写 | Linux WebKitGTK 渲染与 GPU 差异（issue #3988、Nvidia 崩溃 #9394）；File System Access API 不可用，需换 `plugin-dialog` + `plugin-fs` |
| **Electron** | 80–150MB（macOS~150 / Win~120 / Linux~180MB），空闲内存 80–150MB | Win/macOS/Linux，无官方移动端 | ✅ 100% 复用 | 体积/内存；每个应用自带 Chromium 需持续跟安全更新 |
| **Wails v3 (Go)** | 5–10MB（第三方数据~） | 桌面 Win/macOS/Linux；移动端实验性 | ✅ 复用 | v3 仍是 Beta（2026-08-02 发布）；像素类案例少 |
| **Pake** | 基于 Tauri，宣称比 Electron 小约 20 倍 | Win/macOS/Linux | ✅（注入 JS/样式） | 面向 URL 场景，能否直接吃本地单文件 HTML 未验证；GPL-3.0 |
| ~~Nativefier~~ | — | — | — | **已于 2023-09-29 归档、明确不再维护**，不要用 |

参考实例：GlyphStudio（Tauri2 + React + Rust，自带 MCP server）、Imagine-plus（Tauri2 图像工具，macOS 包 ~9MB vs Electron 100MB+）。

### 形态 2｜原生自绘 GUI（重写，但视觉与性能最可控）
| 框架 | 语言 | 体积 | 跨平台 | 像素/图像类实例 |
|---|---|---|---|---|
| **egui** | Rust | Windows release 二进制 ~2.5MB | Win/macOS/Linux + Android；可导出 WASM | Tarsila（像素画 + spritesheet 编辑器） |
| **iced** | Rust | 无官方数据（未验证） | 桌面 + WASM（实验性），无官方移动端 | pxrs（⭐3，案例弱） |
| **Slint** | Rust/C++/JS/Python | 运行时 <300KiB RAM | 桌面 + Android + 嵌入式 + WASM | 无像素编辑器实例（未验证） |
| **Avalonia** | C#/.NET | self-contained ~60MB，NativeAOT+UPX ~15MB | Win/macOS/Linux + iOS/Android + WASM | PixiEditor（⭐8.0k，C#/Avalonia + SkiaSharp + 自研 Drawie） |
| **Flutter** | Dart | 压缩包 ~18MB | 桌面 + iOS/Android + Web | flites（AGPL-3.0，精灵图编辑器，⭐44） |
| **Qt/QML** | C++/PySide6 | C++ 小；PySide6+PyInstaller onedir ~118MB，Linux 易误打包 QtWebEngine >600MB | Win/macOS/Linux + Android/iOS | Krita（⭐5.6k，GPL-3.0）；PsPixel |
| **Compose Multiplatform** | Kotlin | Hello World ~44MB（安装后 ~103MB） | 桌面 + Android/iOS 稳定，Web Beta | 无像素/图像编辑器实例（未验证） |

要点：自绘框架 = 视觉完全可控（美观化上限高），但现有 Canvas/JS 逻辑要整体重写；许可需逐个核对（Qt LGPL 合规、Slint Royalty-free 限制、Flutter BSD-3、Avalonia MIT、egui/iced MIT）。

### 形态 3｜一份核心 + 多外壳（架构上最"省未来"）
- **Rust 单核心多产物**：一个 crate 同时声明 `crate-type = ["lib", "cdylib", "staticlib"]` 与 `[[bin]]`，一份算法即可产出 CLI、Rust 库、C ABI 动态库（供引擎/其他语言）。注意 Rust 无稳定 ABI，跨语言必须走 `extern "C"` + 绑定生成器。
- **绑定层选择**：`wasm-bindgen` + `wasm-pack`（浏览器/Node WASM）；`napi-rs`（Node 原生插件，Node-API ABI 跨版本稳定）；`PyO3` + `maturin`（Python wheel，abi3 可一份 wheel 覆盖多版本）；`UniFFI`（Swift/Kotlin 移动端，官方明确尚未 1.0）；`cbindgen`（C 头文件 → Unity/Godot，官方自述维护较 adhoc）；`godot-rust/gdext`（Godot 4 GDExtension，无需 C 中间层）。
- **已验证的同类先例**：`resvg-js`（同一 Rust 核心出 napi 与 WASM 双后端）、Photon（Rust 图像库 → Web WASM + Node 包）、Biome / SWC（同一核心出 CLI + 原生 + WASM，工业级）。
- **代价**：CI 需覆盖多平台多架构矩阵；绑定层版本易漂移（wasm-bindgen 两侧 schema 必须完全一致）；WASM 平均比原生慢约 45–55%（USENIX ATC'19 数据，现代 JIT/SIMD 下差距缩小但存在）。

### 形态 4｜Web 平台增强（不离开浏览器，但补齐短板）
- **PWA**：可安装、离线、拖放导入；`file_handlers` 让已安装 PWA 成为系统文件处理器，但**仅 Chromium 桌面**（MDN 标注 Limited availability）。注意 PWA 需 HTTPS + Service Worker，`file://` 单文件变不成 PWA。
- **性能**：WASM SIMD 全球约 95.69%；WASM threads 需 COOP/COEP；OffscreenCanvas 自 2025-09-27 起 Baseline 广泛可用（Worker 里渲染大图）；WebCodecs（`VideoDecoder`）可逐帧解码视频，Chrome/Edge 94+。
- **存储**：OPFS 已 Baseline 广泛可用（Chrome 108+、Safari 15.2+/16.4+、Firefox 111+），但用户不可见，不能替代"保存到用户目录"。
- **移动端打包**：Capacitor（系统 WebView + 插件，应用体积可优化到 ~6MB 级）；Cordova 生态老化不推荐。
- 实测参考：fast_image_resize wasm32 基准（RGB8 4928×3279→852×567 Bicubic）124.81ms（非 SIMD）→ 15.43ms（simd128）；TF.js MobileNet：WASM 122.7ms → WASM+SIMD 34.6ms → +threads 12.4ms。

### 形态 5｜引擎插件（产出直接进游戏工程）
- **Godot**：`GDExtension`（Rust/C++ 原生共享库，编辑器与导出项目共用，可跨平台含 Web 但需逐平台编译 + 线程变体匹配）；`EditorPlugin`/`EditorImportPlugin`（纯 GDScript，零编译、易做 UI 与自定义导入器，性能较弱）。
- **Unity**：Editor C# 扩展 + `ScriptedImporter`（自定义资产导入器）；官方 `com.unity.2d.aseprite` 直接吃 `.aseprite`（导入模式 Sprite Sheet / Animated Sprite / Tile Set，默认 Point 过滤、无压缩）；重算法走 Native Plugin（C ABI，Rust 可接）。
- **真实像素插件案例**：Aseprite Wizard（Godot，MIT，自动导入器 + inspector dock，**强依赖用户本机装 Aseprite**，因 Aseprite EULA 禁止再分发 CLI）。
- **与既有交付契约的关系**：`PixelGameDevTools` 已定「sheet.png + sheet.json(Aseprite JSON Hash) + .aseprite 源 + 预览」四件套；插件形态正是让 Unity/Godot 免适配消费这套产物——工具侧只需保证四件套规范，不必自己做引擎插件。

### 形态 6｜宿主美术软件插件（寄生在用户已有的编辑器里）
| 宿主 | 接口 | 能力 | 对 Agent 友好度 |
|---|---|---|---|
| **Aseprite** | Lua API + `-b --script` headless CLI（`--sheet` / `--data json-hash` / `--split-layers` / `--trim`） | 像素场景事实标准，正好覆盖四件套 | ✅ 已有多个 MCP（diivi ⭐517、MalloyTheDev、zerotian 104 工具等） |
| **Krita** | Python (LibKis) + `--export` / `--export-sequence` | 分层/动画导出，sprite sheet 插件生态 | ⚠️ CLI 仍启动完整 Krita，非真 headless |
| **Blender** | `bpy` + `blender -b -P` | 批处理/3D 管线，不是像素编辑器 | ⚠️ 缺网格/索引色能力 |
| **GIMP** | Script-Fu / Python-Fu + `-i -b`、GEGL | 通用图像处理 | ⚠️ 语法老、生态弱 |
| **Photoshop** | UXP（JS） | 商业生态 | ❌ 闭源订阅、无真 headless |
| **PixiEditor / LibreSprite** | 无插件宿主 | 独立跨平台应用；LibreSprite 有 JS 脚本 API | ❌ PixiEditor 至今无 CLI（官方论坛提案仍 open） |

注意：Aseprite 是专有软件，EULA 禁止再分发副本——**不能把它的 CLI 打包进你的工具**，只能要求用户自装（LibreSprite 是 GPLv2 分叉，但 API/生态弱）。

### 形态 7｜Agent 原生形态（把"能被 Agent 调用"当一等公民）
- **MCP server**：事实标准，当前稳定规范 **2026-07-28**（已用 `gh api` 核验 schema 目录存在）；传输分 stdio（客户端 spawn，本地单客户端）与 streamable HTTP（localhost 共享 daemon）；返回 `text` / `image`(base64) / `resource_link`，失败用 `isError=true`。
  - **图像返回最佳实践**：小图 inline base64，大图写 `out_path` 或返回 ResourceLink（atelier 实测 inline 上限 8MiB base64，超限要求落盘）——避免 base64 吃爆上下文。
- **CLI 契约**（clispec.dev v0.2 六原则）：结构化输出（`--format json`）、schema 自省、stdout/stderr 分离、无 TTY 不阻塞、幂等/可重试（`changed` 布尔、dry-run）、有界输出；每条错误声明 exit code，结构化错误 envelope 作 stderr 最后一行。
- **Agent Skill（SKILL.md）**：`SKILL.md`（frontmatter: name/description 必填）+ `scripts/`（确定性后处理）+ `references/`（按需加载）+ `assets/`；progressive disclosure 控制上下文。
- **本地 daemon / HTTP API**：loopback-only + Bearer token + import/export 根目录白名单 + 请求体/并发上限 + 乐观锁 revision + journal 可重放（atelier 的完整范式：127.0.0.1:8765/mcp、1MiB 请求体、64 并发、`expected_revision` 冲突返回 `revision_conflict`）。代价：端口/鉴权/生命周期管理成本，且 macOS 无 systemd --user 需容器或 stdio。
- **结构化产物契约**：Aseprite sprite sheet JSON（json-hash/json-array）、TexturePacker JSON Hash（事实标准，官方 schema URL 未验证）、OpenRaster `.ora`（zip + `mimetype` 首文件 STORED + `stack.xml` + `data/` + `Thumbnails/thumbnail.png`，规范 v0.0.6）、PSD（psd-tools / ag-psd 成熟，Rust 侧未验证）。
- **像素领域已有 Agent 接口盘点（⭐ 采集 2026-09-09）**：diivi/aseprite-mcp ⭐517 MIT Python；willibrandon/pixel-mcp ⭐138 MIT Go；willibrandon/pixel-plugin ⭐314 MIT（Claude Code 插件）；MalloyTheDev/aseprite-mcp ⭐8；rkdfx/aseprite-mcp ⭐12；ayigityol/aseprite-mcp ⭐7（43 工具）；Vollkorn-Games/aseprite-mcp ⭐0；marmikshah/atelier ⭐7 MIT Rust（CLI+stdio MCP+HTTP MCP+daemon，25 工具）；rxolve/pixscii ⭐3（离线确定性 hex-grid 像素 MCP）；artokun/comfyui-mcp ⭐732；0x0funky/agent-sprite-forge ⭐4053（Codex skills + 确定性后处理）。

### 形态 8｜宿主内嵌插件（把工具塞进用户已在用的软件）
- **VS Code 扩展**：Webview API 内嵌任意 HTML/JS/CSS，并可在扩展宿主 Worker 里跑 WASM/WASI；Agent 可通过命令面板/CLI 触发。已有大量图像查看/编辑扩展先例。
- **浏览器扩展（MV3）**：Service Worker 无 DOM/Canvas，需 `chrome.offscreen` 创建离屏文档才能用 canvas —— 是"网页里处理像素"的可行路径，但生命周期与消息传递复杂，且仅覆盖 Chromium。
- **Obsidian 插件**：`registerView` 注册自定义视图渲染任意 HTML/Canvas；已有插件直接在库内渲染本地 `.html` 文件——**这是单文件 HTML 工具"零改造进笔记流"的最低成本宿主**。
- **ComfyUI 自定义节点**：前端 JS 可把 div/canvas/video 嵌入节点，后端 Python；Agent 可通过 HTTP API 触发（已有 Comfy-Canvas 把分层画布编辑器放进工作流）。
- **Figma 插件**：`figma.showUI()` iframe 内可写任意 HTML/Canvas，但无法直接读写画布像素，需走导入/导出；WebGL/WebGPU 可用性未验证。
- **Raycast 扩展**：Node.js + React，无 DOM/Canvas，图像处理需调本地 CLI/子进程；仅 macOS。

## 五、三条推荐路线

**路线 A｜最小改动（1–2 周可出桌面版）**
现有 HTML 原样塞进 **Tauri 2**；把 `showOpenFilePicker` 换成 `plugin-dialog` + `plugin-fs`；补一个 `--headless` 的 CLI 入口（Rust 侧或 Node 侧）供 Agent 调用。
→ 满足 1/2/3；Agent 友好度靠后加的 CLI/MCP 补齐。

**路线 B｜一核多壳（3–6 个月，长期最优）**
① 把现有 JS 算法抽成纯函数 + 明确 I/O 契约（像素缓冲/参数进，sheet+JSON 出）；
② Rust 核心 crate（只依赖 image / png / palette / fast_image_resize 等，禁止绑定代码进核心）；
③ 先出 **CLI + WASM** 两个壳（成本最低，Agent 与浏览器都能用）验证算法一致；
④ 按需加 napi-rs（Node）、PyO3（Python）；
⑤ 移动端/引擎插件留最后（UniFFI / gdext / C ABI）。
→ 四条硬指标全满足，且未来任何新形态都是"加壳"而不是"重写"。

**路线 C｜Agent 原生优先（轻前端、重契约）**
保持单文件 HTML 作为 UI，同时把核心能力暴露为 **MCP server（stdio + HTTP）** 与 **结构化 CLI**，产物直接落 `sheet.png + sheet.json + .aseprite + preview.png` 四件套；配一个 `SKILL.md` 告诉 Agent 何时用哪条命令。
→ 对"人 + Agent 双通道"收益最快，性能靠 WASM 版核心补齐。

**决策提示**
- 只要"能跨平台跑、体积小、别重写"→ A。
- 想要"性能 + 全平台 + Agent 原生，且愿意投入"→ B。
- 眼下最痛的是"Agent 用不起来/产物不标准"→ C。
- 三个都要 → B + C（B 的 CLI/MCP 壳就是 C 的实现）。

## 七、风险与未验证项（宁缺毋假）

1. **Tauri Linux 性能未实测**：WebKitGTK 下大图/视频帧 Canvas/WebGL 的真实性能，需在目标发行版上本地 benchmark（官方 issue #3988 存在）。
2. **File System Access API 依赖审计未做**：需先确认现有单文件 HTML 是否依赖 `showOpenFilePicker` 等（决定 Tauri/Wails 迁移工时）。
3. **WASM 首屏体积与加载耗时未实测**：各壳的真实包体需按项目自测。
4. **WebGPU "比 WASM 快 5–60 倍"仅见厂商博客**，缺独立可复现基准；不能作为主路径唯一依据。
5. **TexturePacker JSON Hash 官方 schema URL 未验证**；Aseprite JSON 无版本化规范，跨版本字段漂移需自建转换器兜底。
6. **egui/iced 各平台 release 体积无官方统一数据**；Compose MP、Slint、iced 在像素编辑器领域均无生产级开源实例（未验证）。
7. **atelier 自述"100% AI 编写、无人类逐行 review、无 release"**：接口设计可参考，不宜直接生产依赖。
8. **"Agent 调用成本"为架构判断**，无量化数据（未验证）。
9. **许可风险**：imagequant 为 GPL-3.0-or-later（闭源商用需替换为 quantette 或购 pngquant 商业授权，条款未验证）；Qt LGPL 合规、Slint Royalty-free 限制需逐条核对。
