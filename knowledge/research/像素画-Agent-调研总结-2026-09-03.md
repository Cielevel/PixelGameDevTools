# 让 Agent 作像素画：技能与仓库调研总结

> 探索日期：2026-09-03 ｜ 采集：AtlasBrain（探索主题由 Cielevel 指定：作静态像素画、动态像素画；评估维度：提升准确度、一致性、降低幻觉）
> 完整档案：知识库 ShelfGithub/ecosystem/pixel-art-agent-tools.md（导览）+ Shelf/ai/pixel-art-agent-drawing.md（方法论）+ ShelfGithub/deepdive/（13 个 repo 独立档案）

## 一句话结论

像素画是 AI Agent **天然友好**的作画媒介：网格坐标 + 索引色 + 结构化格式（字符网格 / JSON / HTML / 脚本）= 输出可校验、可读回、可预览——幻觉被**结构性抑制**，而不是靠模型自觉。⭐ 数据采集于 2026-09-03。

## 为什么像素画能提升准确度 / 一致性 / 降低幻觉

1. **状态空间小且离散**：画布 = 有限网格（8×8 ~ 256×256），坐标与颜色是枚举 token，服务端可校验（越界/非法色直接拒绝）→「画飞」结构性不可能
2. **索引色与调色板约束**：色板集合封闭（NES / Game Boy / PICO-8 / Sweetie16 等硬件色板，可经 Lospec API/CLI 程序化取用），任意色量化映射回集合 → 没有「凭空造色」
3. **结构化中间格式**：字符网格、JSON 精灵定义、行整数数组、HTML/CSS、Lua 脚本 → 可 inspect / diff / 回滚 / 单测，错误显式可查
4. **反馈闭环**：每步操作返回 PNG 预览、像素真值读回、onion-skin、帧 diff → Agent「先看再改」（pixelsmith 原话：能看见自己输出的 Agent 迭代远好于盲画）
5. **确定性管线**：经典算法（Pyxelate/PixelOE）无采样 → 同输入同输出、可复现
6. **参考锚点**：生成式场景用 reference_asset_id + 资产清单约束大批量一致性

## 三条技术路线

| 路线 | 代表 | 一致性 | 幻觉风险 | 代价 |
|---|---|---|---|---|
| 生成式（云端文生图/视频） | SpriteCook skills、Pollinations | 靠参考锚点（弱） | 高 | 付费/额度、不稳定 |
| 工具式（MCP 画布/编辑器） | pixel-mcp、pixelsmith、aseprite-mcp 系 | 靠色板+画布状态（中强） | 低 | 本地依赖（Aseprite 需授权） |
| 确定式（转换/程序化/引擎） | PixelOE、pyxelate、Visecity、pyxel | 结构性保证（最强） | 近零 | 需源图/写定义 |

## 静态像素画 · 候选仓库/技能

- **pyxelate**（sedthh/pyxelate，⭐~1,687，MIT）—— 经典算法图→8-bit 像素画；fit 一次色板复用于多图 = 批量风格一致；`pip install` 即用
- **PixelOE**（KohakuBlueleaf/PixelOE，⭐~489，Apache-2.0）—— 无 AI 的细节保留像素化（对比度感知 + 轮廓扩展），ComfyUI 节点 + CLI
- **YoYoPixel**（SbName/yoyopixel，⭐~5，MIT）—— 无 GPU：任何文本 LLM 输出 HTML/CSS/JS，浏览器渲染成像素画；8×8 图标到 256px 场景 + tileset 模式
- **pixel-art-generator**（Visecity，0★）—— JSON/DSL 精灵定义 → 确定性渲染（16×16/16×32），完全可复现
- **pixel-mcp**（ehm-93，0★，MIT-0）—— spec 驱动的索引色画布 MCP，网格文本编辑 + 参考图量化 + 质量 lint，导出 PNG/GIF/aseprite_json

## 动态像素画 · 候选仓库/技能

- **Aseprite**（aseprite/aseprite，⭐~39,172，EULA）—— 行业标准动画精灵编辑器，headless CLI + Lua 脚本 = Agent 动画的工业后端
- **aseprite-mcp · ZeroTian**（0★，MIT）—— 104 工具/17 类：24 个动画工具（帧/cel/tag/补间）、onion-skin、帧 diff、动画一致性校验；演示：Claude 端到端画 32×32 剑士 + 4 帧挥剑动画 + spritesheet
- **aseprite-mcp · jcscocca**（0★，MIT）—— headless Lua 驱动；字符网格 I/O（draw_grid/read_pixels）+ preview 图片返回（可叠坐标网格）
- **pixelsmith**（liamlz11/pixelsmith，0★ prototype，MIT）—— 精灵编辑器 + 动画引擎 MCP，**每步返回 PNG 预览**，关键帧/程序化运动，导出 GIF/APNG/spritesheet
- **pyxel**（kitao/pyxel，⭐~17,789）—— Python 复古引擎：动画/场景全代码化 = 动态像素画的「可复现程序」路线
- **SpriteCook skills**（⭐~30，MIT）—— 生成/动画/Godot 端到端技能集（云端服务，reference_asset_id 保一致）
- **Pixel Art Studio**（Synero，⭐~8）—— 照片转换 + 文生图 + **文生动画 MP4/GIF**（Pollinations，零 key）；**Hermes 上游 pixel-art 技能的调色板来源**

## 工程落地记录（2026-09-03，同日采纳）

对照本工程既有工具链（`tools/pixelart/`，Python + Pillow 脚本化路线）评估，可增强项已落地：

**已采纳（5 项）**

| 调研来源 | 落地 |
|---|---|
| aseprite-mcp 系「帧 diff / 动画一致性校验」 | `check.py` 新增动画一致性检查：**死帧（相邻帧像素全同）P1 门禁**；帧间跳变、循环首尾突断 P2 提示；阈值按全 34 组既有资产实测校准零误报 |
| 同上「动画统计」 | `pixcli anim`：相邻/循环帧间 diff 率、不透明面积序列，信息用不设门禁（FX 类动画面积剧变属正常，交审查解读） |
| aseprite-mcp「onion-skin」 | `pixcli onion`：洋葱皮静态检查图（红=上一帧、蓝=下一帧、首尾回绕），审查运动弧线/循环衔接/锚点抖动 |
| aseprite-mcp·jcscocca「preview 可叠坐标网格」 | `pixcli contact --grid`：放大检查图叠 1px 像素网格、每 8px 亮线并标坐标刻度，审查可引用精确像素坐标 |
| pixel-mcp「参考图量化」/ pyxelate「色板映射」思路 | `pixcli quantize`：任意图归入工程调色板 + alpha 两态化（包装既有 `palette.quantize`/`enforce_alpha`），模仿/导入路径的结构性保色 |
| 确定式路线「可复现、零差异验证」 | `pixcli diff`：像素级比对，文件↔文件或目录↔目录，一致 exit 0（服务「重构/改参后零像素差异」验证场景） |

同步更新：`tools/pixelart/README.md`、6 个 pixel-* agent 定义（artist/reviewer/full/imitator/imitator-reviewer）。程序化门禁口径不变（`pixcli check` exit 0），仅检查项增强。

**不采纳（及理由）**

- Aseprite headless + aseprite-mcp / pixelsmith：Aseprite 非 OSI 许可、引入本地重依赖，违背「Pillow 外无依赖、产物 git 友好」约束；其能力已由脚本化等价实现
- 生成式路线（SpriteCook / Pollinations / 上游 hermes pixel-art 技能）：幻觉高、依赖云端服务、与「脚本可复现」冲突；本工程无需照片转像素画
- pyxelate / PixelOE 库：图→像素画转换场景本工程不存在（从零绘制+模仿），且引入额外依赖不值；量化需求已由 `quantize` 覆盖
- Lospec API：外部网络依赖；工程调色板已定案固化于 `assets/palettes/`
