# 像素视频：高清素材路线评估（2026-09-08）

> 日期：2026-09-08
> 关联：`pixel-toolkit/video-studio.html`、`pixel-toolkit/video.py`、`knowledge/像素视频-工具改进方案.md §8`、`knowledge/参考图生成约束.md`
> 状态：评估稿（含实测数据，复现命令见文末附录）；**2026-09-09 补记素材侧「大色块」口径（§7）**
> 阅读对象：本人 + 各 agent（pixel-artist / pixel-imitator / reviewer 系）

> **决策（2026-09-08，用户拍板）**：优先级 = 能被 Web / Unity / Godot 等游戏工程直接消费的**可编辑资产**；AI 视频降级为**动作参考**，不再作为交付物。§5 的两条分叉自此收口——走「游戏资产」列，不走「像素化视频」列。交付规格见 `agent-pipeline/shared/跨引擎交付契约.md`。

---

## 1. 待评估命题

**现有路线**：生图 AI（Nano Banana）出参考图 → omni / veo 出动作视频 → 投入 `video-studio.html` 按流程调参 → 导出。

**新想法**：Nano Banana 做高清图 → omni / veo 做高清动作视频 → 工具拆帧 → 拼成高清 sheet → 标准像素化 → 验证播放。

**观察到的现象**：视频像素化陷入"古怪的循环"——生成素材 → 像素化 → 看着闪 → 调参 → 还闪 → 换素材 → 重新生成。

---

## 2. 结论摘要

1. **新想法是一次「输入升级」，不是「范式修正」。** 它改善的是源素材质量（分辨率、压缩伪影），不改变产出方式：管线仍是逐帧独立重采样。而闪烁的根因在范式，不在素材——`像素视频-工具改进方案.md` §8.1 已定义。
2. **实测证实根因与素材质量无关**：即使只看「全程不透明」的静止格（应当恒定），帧间颜色翻转率仍达 **33.2%（旧素材）/ 49.1%（新素材）核心格**。换更干净的源不会让这个数字归零。
3. **「高清视频 → 标准像素化」缺一个前提**：源视频必须持有稳定逻辑网格。实测两段 AI 视频的网格检测**帧间跳变**（cell 在 2×3 与 8×7 之间乱跳），且推断的逻辑分辨率 ≈182×102（旧素材，按 cell 7×7 算）/ 160×120 ~ 640×240（新素材，按 cell 跨度算），每轴比 64×64 目标档位细约 3~10 倍——**最后一步必然还是降采样**，即回到现状。
4. **真正能打破循环的是两件事，不是更好的素材**：① 客观判据（把「帧间变色率」变成门禁，调参有数）；② 交付形态决策（要游戏可用资产，就走重绘路线，闪烁从结构上消失）。
5. **顺带收益最高的改动是「时间维滤波」**：成本极低，实测把核心格帧间变色率从 33.2% / 49.1% 降到 **9.6% / 21.5%**。建议先做这一步，再谈换素材。
6. 高清素材仍有其**真实价值**：边缘更干净（4:2:0 色度子采样与压缩过渡带在输出端占比更小）。它解决"边缘脏"，不解决"内区颜色漂移"。

## 3. 实测证据（2026-09-08）

**测法**：ffmpeg 抽帧（12fps）→ 抠像（绿幕/蓝幕，蓝幕口径对齐 `video-studio.html` 的 blue 主判定 + 弱判定边缘清除）→ 全程 alpha bbox 裁剪 → 等比降采样到 64×64 → 跨帧共享 OKLab 16 色板 → 统计。

### 3.1 网格稳定性（`standardize.detect_grid`，逐帧）

| 素材 | 检测 cell（5 帧 @1fps） | conf | 推断源逻辑分辨率 | 判定 |
|---|---|---|---|---|
| `dog_walk.mp4`（绿幕，09-06） | (7,7) (7,7) (7,7) (7,7) (7,8) | 0.64~0.68 | ≈182×102 | cell 不稳定、置信度低 |
| `Pixel_art_walking_animation…mp4`（蓝幕，09-08） | (8,6) (8,7) (2,3) (2,3) (2,3) | 0.79~0.83 | ≈160×120（首帧 cell 8×6）；按 cell 跨度 160×120 ~ 640×240 | cell 帧间跳变 |

结论：AI 动态视频**没有可用于还原的逻辑网格**（与 `samples/dog/video/README.md` 的既有实测一致）。"高清"不会凭空长出网格——视频模型输出的是连续色调帧。因此「拆帧 → 高清 sheet → 标准像素化」在缺网格前提时，会退化成「高清帧 → 降采样」，与现状同构。

### 3.2 时间稳定性（现有管线，64×64 + 共享 16 色板）

「静态格」= 全程不透明（始终被主体覆盖）的格；「核心格」= 静态格再腐蚀 1px（排除轮廓带，取真正的内区）。**这些格在任何正常像素动画里都应保持颜色恒定。**

| 素材 | 静态格 / 核心格 | 帧间变色率（全部 / 核心） | 单格平均色数 | 叠加时间中值(5)后（全部 / 核心） |
|---|---|---|---|---|
| `dog_walk.mp4` | 1179 / 973 | 38.6% / **33.2%** | 4.17 | 12.0% / **9.6%** |
| 蓝幕新素材 | 785 / 629 | 48.8% / **49.1%** | 4.78 | 21.3% / **21.5%** |

读法：新素材的核心静止格平均每两帧就变一次色——这不是"素材不够好"，这是逐帧重采样 + 网格相位漂移的必然产物。

### 3.3 顺带发现的缺陷：`video.py` 的非绿幕去背景失效

`remove_bg_connected` 以**画布边界**为种子做 4-连通清除。而 `--fit contain`（默认）会在画布上留透明边条（alpha=0、RGB=0,0,0），种子像素与背景色距离过大 → 连通生长根本进不去 → **背景完全不清除**。

- 合成验证：64×36 蓝底 + 白方块，contain 进 64×64 → 不透明 2304 格；`remove_bg_connected` 后仍 2304 格（无变化）；对照组（无留边）4096 → 576 格（正常清除）。
- 影响面：`pixcli video-std` 对**非绿幕素材**（含蓝幕）产出的是不透明背景帧。
- `video-studio.html` 不受影响——它在**原始分辨率**先抠像再降采样（`keyApply` → `cropToBox` → `downsampleContain`）。
- 另一处口径落差：`video.py` 的幕色判定只有绿幕（`detect_green_screen`），而 `video-studio.html` 已支持 绿/蓝/品红/青 + 自由取色。CLI 与工作台能力不对等。

## 4. 新想法：解决什么、不解决什么

| | 高清素材路线 | 说明 |
|---|---|---|
| 边缘伪影（色度子采样、压缩过渡带） | ✅ 改善 | 过渡带以源像素计，源分辨率越高、降采样后占比越小；用户在 `video-studio.html` 注释中记录的"24 帧 1098 个可见偏蓝边界格"属此类 |
| 轮廓/细节可读性 | ✅ 改善 | 采样输入更干净，鲁棒采样（众数/mean-shift）更有效 |
| 迭代成本 | ✅ 改善 | 一次生成贵素材，之后本地无限迭代——把"AI 生成"与"调参"解耦，这一点对打破循环最有价值 |
| 内区颜色漂移 | ❌ 不改善 | 根因是输出网格钉在屏幕坐标、主体在动；与源分辨率无关。源越细，每格平均的源像素越多，漂移只会更"平滑"而非消失 |
| 网格还原（标准像素化） | ❌ 前提不成立 | 实测 AI 视频无稳定逻辑网格；且逻辑分辨率每轴比目标档位细约 3~10 倍（按像素数 8~100 倍） |
| 跨帧一致性 | ➖ 结构上正确 | sheet 化统一网格与色板方向对，但前提是各帧逻辑像素严格同相位——实测帧间 cell 就在跳 |

**与既有文档的口径冲突（需澄清）**：`knowledge/参考图生成约束.md` 明确"参考图是**设计规格书**，不是待缩放的原图"，"算法缩放在 32px 档位会糊成泥"，转换侧应逐像素手绘。新想法中的"标准像素化"若指把高清图算法缩到目标档位，与该口径直接冲突；若指 `standardize` 的网格还原路径，则依赖上面被实测否掉的前提。**二者只能取其一，不能并存**。

## 5. 循环的出口

循环之所以闭合不上，不是素材不够好，是缺两样东西：

1. **客观判据（收敛门禁）**：现在只有"肉眼看着闪不闪"。建议把 §3.2 的「核心格帧间变色率」固化为可复跑的门禁指标（如 `pixcli stability`），阈值先定 **≤5%**，每次调参看数不看感觉。
2. **交付形态决策**：这决定了要不要走"像素化"这条路本身。

| 目标 | 推荐路线 | 闪烁问题的归宿 |
|---|---|---|
| 游戏引擎可消费资产（可编辑 sprite / 可回 aseprite 改） | `像素视频-工具改进方案.md` §8.2 方案 C（姿态驱动骨架）或 `agent-pipeline/` 的 imitator（有源参考的模仿绘制） | **结构性消失**——颜色从未被重采样；此时高清视频只是动作参考，甚至可以低清 |
| 仅"像素化的视频"（非游戏消费，观看/演示用） | 现有管线 + 时间维滤波 + 相位锚定 | 降到可接受范围（实测 9.6%~21.5%） |

## 6. 建议路径（按性价比排序）

1. **时间维滤波**（半天）：在跨帧共享色板之后，对每个输出格做 ±2 帧窗口的中值/众数投票，再归回共享色板。实测核心格帧间变色率 33.2%/49.1% → 9.6%/21.5%。改动点集中在 `video.py::video_standardize` 的量化后阶段与 `video-studio.html` 的 `mapToPalette` 之后。
2. **判据入库**（半天）：把 §3.2 度量做成 `pixcli stability`（或 `check --temporal`），让"调参"有客观收敛信号。
3. **高清路线的前置验证（30 分钟，一次即可，不要变成新一轮循环）**：
   - 用 3 个模型各生成 1 段 3 秒"**粗网格**像素风"视频，prompt 明确要求"角色宽约 64 逻辑像素、方块边缘锐利、网格稳定"；
   - 用 `detect_grid` 逐帧测 cell/conf；
   - **通过判据**：cell 帧间恒定 + conf > 0.9 + 推断逻辑分辨率落在目标档位附近。不达标即判定此路不通，回到第 1/2 步或转方案 C。
4. **若目标含游戏资产**：直接转方案 C / imitator，高清素材的价值退化为"更好的动作参考图"，不必为像素化再投成本。
5. **修复 `video.py` 去背景缺陷**（可选）：在 `remove_bg_connected` 之前先把透明留边剥离（或在未降采样的原始帧上做背景清除），并补齐蓝/品红/青幕色判定，与工作台能力对齐。

## 7. 素材侧补充（2026-09-09）：有效的是「大色块」，不是高分辨率

> 来源：用户实测观察（2026-09-09），**未做 §3 口径的量化复测**。本条是**素材生成口径**，工具侧不改——`video-studio.html` / `video.py` 保持现状即可受益。

**观察**：让 AI 生成的源视频采用「大色块」风格——每个部位大面积平涂、边界硬、纹理与渐变极少——再走现有 `video-studio.html` 转换，像素抖动明显减少，比同样高清但带纹理/渐变的素材更稳、更适配当前管线。

**机理（与 §3.3、工具方案 §8.1 的根因一致）**：闪烁来自逐帧独立重采样——输出格在源帧上的覆盖位置随运动连续滑动，格内混色均值跟着滑动，量化后就在色板条目间跳变。大色块让**块内部**在空间上是常量色：亚像素位移不改变格内均值 → 内区格颜色恒定，剩余抖动只落在运动边界带（轮廓带），而轮廓带逐帧变化在像素动画里属正常现象。即抖动从「内区漂移」退化为「边缘爬行」——前者是问题，后者可接受。

**与高分辨率的关系**：高清只减小边缘过渡带占比（治"边缘脏"），不改变"格内混色随运动滑动"的机制（§4 表）；大色块直接从源头削减格内混色的方差。两者正交——**大色块优先，高清是加分项**。

**与时间维滤波的关系（互补，不替代）**：
- 时间维滤波只压静止区域，且窗口越大越容易拖影（`像素视频-工具改进方案.md §2` 的运动感知门即为此而加）；
- 大色块素材让更多格落在"块内部"（静止区域占比上升、单格色数下降），滤波要修的量更少、可用更小窗口，拖影风险更低；
- 当前最优组合：**素材侧选大色块 + 工具侧时间众数/稳定档**。

**生成侧约束（可直接并进 prompt，与 `参考图生成约束.md` 同类口径一致）**：

| 要 | 不要 |
|---|---|
| 平涂 / 硬边赛璐璐，色块边界锐利 | 软渐变、喷枪、厚涂 |
| 每部件明暗 2–3 阶 | 复杂光照、环境光、轮廓光 |
| 大色块分区做识别特征（服装主色块、剪影型特征） | 花纹/刺绣/纹理贴图等细碎特征 |
| 有限色板，色数少而稳 | 噪点、胶片颗粒、dither 抖动质感 |
| 纯色幕背景（绿/蓝，与主体色相远离） | 场景背景、投影、景深、运动模糊 |
| 动作幅度克制、匀速（缩小边界带面积） | 快速大幅动作、透视夸张 |

若模型支持像素/网格风：一并要求「粗网格、方块边缘锐利、网格稳定」（判据同 §6.3 前置验证）——网格稳定时还可走 `video-studio.html` 的原生网格重采样，进一步减少降采样混色。

**口径提示**：§2 结论不变（高清素材不是闪烁的解），本节补上的是素材侧**真正有效的那根轴**；`像素视频-工具改进方案.md §6`「素材侧：高清输入不解决闪烁」应读作「**仅**提高分辨率不解决」。

## 8. 附录：复现命令

环境（本机无系统 ffmpeg，用 `uv` 临时取 imageio-ffmpeg 提供的二进制）：

```bash
# 抽帧 + 逐帧网格检测（用仓库自带 standardize.detect_grid）
uv run --with pillow --with numpy --with imageio-ffmpeg python - <<'EOF'
import sys, subprocess, glob, os, tempfile, imageio_ffmpeg
sys.path.insert(0, "pixel-toolkit")
from PIL import Image
import standardize as S
FF = imageio_ffmpeg.get_ffmpeg_exe()
src = "samples/character/pixel_walk/Pixel_art_walking_animation_202609080040.mp4"
td = tempfile.mkdtemp()
subprocess.run([FF, "-y", "-loglevel", "error", "-i", src, "-vf", "fps=1",
                os.path.join(td, "f_%03d.png")], check=True)
for p in sorted(glob.glob(td + "/*.png")):
    g = S.detect_grid(Image.open(p).convert("RGB"))
    print(os.path.basename(p), g["ok"], g["cell"], g["conf"], g["note"])
EOF
```

时间稳定性度量（核心逻辑）：抽帧 → 抠像 → 全程 alpha bbox 裁剪 → `downsample_average(64,64,fit="contain")`
→ 跨帧合并色板 `build_palette_k(k=16)` → `map_with_palette` → 取「全程不透明格」（再腐蚀 1px 得核心格）
→ 统计相邻帧颜色翻转比例；时间中值版：每格取 ±2 帧窗口的逐通道中值，再映射回共享色板。

> 备注：本机 `python3` 无 Pillow、无 ffmpeg；仓库脚本可用 `uv run --with pillow --with imageio-ffmpeg` 临时补齐运行环境。
