# 像素视频 → 稳定像素动画：动作一致性方案

> 日期：2026-09-07
> 关联工具：`pixel-toolkit/video-studio.html`
> 状态：方案讨论稿（待验证，验证结果将回填本节）
> 阅读对象：本人 + 各 agent（pixel-artist / pixel-imitator / reviewer 系）

---

## 1. 问题定义

### 1.1 现状

`video-studio.html` 当前管线：

```
抽帧（区间内均匀采样）→ 抠像（绿幕/自动）→ 固定参考框裁剪（全帧并集 bbox）
→ 逐帧 box 降采样（alpha 两态化）→ 跨帧共享 OKLab 调色板量化 → 导出
```

已具备的时间稳定性手段：

- **固定参考框**：帧间裁剪窗口一致，主体整体位置稳定
- **跨帧共享色板**：颜色集合全局统一（OKLab k-means，确定性）

### 1.2 痛点（范式错位）

管线本质是**逐帧独立重采样**：每个动作瞬间，画面被重新采样一遍。输出像素格在源帧上的覆盖位置随角色运动**连续变化** → 同一身体部位被不同源像素混合 → 均值颜色逐帧滑动 → 量化到全局色板后在相邻条目间**跳变** → 动画中角色部位颜色闪烁、边缘爬行。

一句话：当前产出是「被像素化的视频」（per-frame rasterization），不是「像素角色的动画」（sprite animation）。

- 像素化视频：颜色绑定在**空间采样格**上，格随运动漂移，颜色就漂移 —— 稳定性是统计近似
- 像素动画：颜色绑定在**身体部位**上，动画只是形象在动 —— 稳定性是结构保证

### 1.3 目标（验收标准）

- [ ] 动作全过程中，同一身体部位（头/躯干/四肢）像素颜色**恒定**
- [ ] 形状连贯，无边缘爬行、无闪烁、无撕扯
- [ ] 产出形态可消费（预览 / 导出 / 进游戏，按需求分级）
- [ ] 保留现有能力：绿幕抠像、色数控制、均匀抽帧、描边

## 2. 方案

### 方案 A：模板锁帧（Template-Locked）—— 最小改动路线

**核心思想**：先挑一帧把角色「定型」成像素形象（锁死调色板与形状），其他帧不再独立采样，而是**参照模板**生成。

#### A-1 栅格相位锚定（Grid-Phase Anchoring）—— 最快原型

- 问题根因：降采样网格钉在**屏幕坐标系**上，角色一动，网格与角色的相对相位就变，同一部位被不同格覆盖
- 改动：把网格钉在**角色坐标系**上 —— 每帧裁剪窗跟随主体（主体 bbox 位置 + 固定偏移），使主体在输出网格上的相位恒定
- **关键坑**（工具注释已警示）：主体 bbox 边缘在源像素级跳动（±1px），直接锚定会造成整体「台阶抖动」。必须把锚定偏移**量化到输出格粒度**（offset = floor(offset / 格尺寸) × 格尺寸），避免亚像素级跳动，同时保持格相位稳定
- 优点：改动量最小（只动 `processAll` 的裁剪/放置逻辑），当天可验证
- 短板：大幅位移/形变仍会崩（相位恒定只解决「平移型」不稳定）

#### A-2 光流搬运（Flow-Based Transfer）

- 关键帧定型模板（高质量像素化 + 锁死调色板）→ 相邻帧间计算光流（Farneback / RAFT）→ 模板像素按累积流场搬运到目标帧位置，**颜色直接继承模板，不重新采样**
- 优点：颜色 100% 继承模板，闪烁彻底消失
- 短板：遮挡、大幅形变、流场不连续处出现撕扯；需要光流依赖（OpenCV / onnx 模型）

#### A-进阶 多模板锁帧

- 抽 3~5 个关键姿态帧各自定型，中间帧在相邻模板间插值（morph / inbetween）
- 即传统像素动画的「原画 + 中间画」思路；中间帧由算法或 AI 补齐

### 方案 B：部件追踪（Part-Tracking）—— 抗大动作版

**核心思想**：把角色拆成部件（头/躯干/上臂/小臂/大腿/小腿……），每个部件**独立**参照自己的模板采样，颜色绑死在部件上。

- **分割**，三选一：
  - 手动：关键帧画掩码分区（颜色相近 ≈ 同部件）
  - 视频分割模型：SAM2 / Cutie / XMem 逐帧跟踪部件掩码
  - 姿态驱动分区：MediaPipe Pose / OpenPose 骨骼点切刚性块
- **每部件独立处理**：以自身掩码圈定源区域 → 各自按 A-1 相位锚定采样 → 颜色继承部件模板色
- **组装**：按遮挡顺序叠回最终帧；关节接缝用「重叠带 alpha 混合」或复用现有 1px 描边能力遮盖
- 优点：部件刚性、各自稳定，扛大幅动作与转身
- 短板：分割质量决定成败；实现量最大；SAM2 系在 Mac 上能跑但慢（MPS）

### 方案 C：姿态驱动骨架（Pose-Driven Rigging）—— 真·像素演员

**核心思想**：彻底跳出「视频→像素」范式。视频只用来**提取动作**，像素角色另画成**分层像素骨架**，用动作数据驱动播放 —— 正统像素动画工作流（keyframe + inbetween 的自动化变体）。

- **角色定型**：aseprite（或 pixcli 流程）把角色画成分层骨架（头/躯干/四肢分层），颜色画死、永不重采样
- **动作提取**：视频跑姿态估计（MediaPipe Pose），输出逐帧骨骼点序列（关节角度 + 根节点位移）
- **驱动播放**：关节角度 → 驱动各像素层 **rotSprite** 旋转（标准技法：先放大 8× 再旋转再最近邻缩回，防失真）；根位移 → 整 sprite 平移
- 优点：
  - 唯一 100% 满足「同部位颜色恒定」的方案 —— 颜色从未被重采样，结构性保证
  - 产出**可编辑资产**，可回 aseprite 继续改、可被游戏引擎直接消费
  - 与循环动画（walk cycle 等）原生兼容
- 短板：等于「做动画」——工作量最大；rotSprite 质量要调；姿态估计对卡通比例（大头小身、非人形）打折，需手动校准映射（关节角 → 精灵关节）

## 3. 对比与选择

| 维度 | A 模板锁帧 | B 部件追踪 | C 姿态驱动骨架 |
|---|---|---|---|
| 工作量 | 小（A-1 当日可验） | 大 | 最大（动画项目级） |
| 抗大幅动作 | 差（平移型可解） | 强 | 强 |
| 颜色恒定保证 | 继承模板，统计级 | 部件级锁定 | 结构性保证 |
| 可编辑资产 | 否 | 半（部件化） | 是 |
| 产出形态 | 序列帧/GIF | 序列帧/GIF | 分层 sprite + 动作数据 |
| 技术风险 | 低 | 分割质量 | rotSprite 失真、姿态映射校准 |

**建议路径**：今日先用 A-1（30 分钟原型）验证「颜色恒定」是否就是目标观感 → 动作幅度大扛不住则升级 B → 若终极目标是可编辑资产/进游戏，直接奔 C，前三者只是过渡。
