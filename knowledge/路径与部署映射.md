# 路径与部署映射（本仓 ↔ 游戏工程）

> **为什么要这份文档**：本仓是**参考库**，工具与 agent 会被**拷贝到具体游戏工程**里使用。因此文档里大量出现的路径（`tools/pixelart/`、`.zcode/agents/`、`assets/sprites/`、`docs/`）指的是**部署后的工程路径**，不是本仓路径。不知道这一点时，读者会把它们误判为失效引用（自动检查会报出几十条）。
> **一句话规则**：文档里写 `assets/…`、`previews/`、`tools/pixelart/…`、`.zcode/…`、`docs/…`、`AGENTS.md` 时，默认都指**目标工程**；写 `pixel-toolkit/…`、`knowledge/…`、`agent-pipeline/…` 时指**本仓**。

## 映射表

| 本仓（参考库） | 部署后（游戏工程） | 备注 |
|---|---|---|
| `pixel-toolkit/` | `tools/pixelart/` | 整目录拷贝；CLI 入口 `pixcli.py` |
| `agent-pipeline/agents/` | `.zcode/agents/` | 8 个 agent 定义（差量文件） |
| `agent-pipeline/shared/` | `.zcode/agents/shared/` | 共同基线：像素资产约定 / 技法纪律 / 审查框架 / 跨引擎交付契约 |
| `agent-pipeline/skills/pixcli/` | `.zcode/skills/pixcli/` | 工具速查与门禁判读 skill |
| `knowledge/像素法则.md`、`参考图生成约束.md`、`即梦生图-Mac自动化手册.md` | `docs/` | 方法论与手册（agent 定义按 `docs/` 引用） |
| `templates/gitattributes` | 工程根 `.gitattributes` | 二进制防换行归一化 |
| `templates/gitignore-pixel-game` | 工程根 `.gitignore` | 起步模板 |
| `templates/pixel-art-repro.yml` | `.github/workflows/pixel-art-repro.yml` | 资产可复现 CI |
| `experimental/`、`knowledge/research/`、`knowledge/standardization/` | **不部署** | 实验与归档 |

## 文档中「部署后路径」的常见清单

- `assets/sprites/<资产>/<名称>_*.png`——像素资产本体（按前缀分子目录）
- `assets/palettes/<名>.json`——工程调色板（`palette.py` 读写格式）
- `previews/`——只放交付给用户看的预览（GIF/HTML/检查图）
- `docs/`——方法论与手册
- `tools/pixelart/…`——工具链
- `.zcode/…`——agent 与 skill
- `AGENTS.md`——**项目基准唯一事实源**（画布档位/朝向集/动作清单/调色板与目录）

## 维护约定

- 新增文档引用**本仓**文件：用仓库相对路径（如 `pixel-toolkit/README.md`）
- 引用**部署后**文件：保持原写法（`assets/sprites/…`），必要时加「部署后：」前缀；**不要**改成 `pixel-toolkit/…`，否则 agent 在目标工程里会找不到
- 本映射表随 `README.md` 的「复用步骤」同步修订
