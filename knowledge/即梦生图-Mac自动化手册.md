# 即梦生图 Mac 自动化手册（computer-use 实测）

用途：在 macOS 上用 ZCode computer-use 驱动 Safari 操作即梦网页版，自动完成「选模式 → 选模型 → 选分辨率 → 生图 → 批量下载 → 逐张读取」全流程，为 `docs/参考图生成约束.md` 的参考图管线提供**机器通路**。该文档管"喂什么 prompt"，本文档管"怎么在 Mac 上把图生成并拿回来"。

本文所有步骤均在 2026-09-04 两轮实测中验证通过（含 Safari 冷启动）。

## 环境前提

- **权限**：辅助功能（Accessibility）+ 屏幕录制（Screen Recording）已授权给 `dev.zcode.cua-helper`。会话开始时 `request_access` 检查一次即可；两项均 granted 才能继续。
- **登录态**：Safari 持久保存即梦登录态，冷启动后无需登录。账号积分、上次使用的模型/比例/分辨率/数量也会被服务端记住。
- **下载目录**：Safari 下载免弹窗直接落 `~/Downloads`。
- **浏览器**：Safari（bundle_id `com.apple.Safari`）。整个流程可全程后台执行（a11y 元素操作），不抢占用户焦点。

## 关键 URL

| 页面 | URL | 说明 |
|---|---|---|
| 图片生成页（推荐直达） | `https://jimeng.jianying.com/ai-tool/generate/?type=image` | 带图片参数条的生图界面 |
| 首页 | `https://jimeng.jianying.com/` | 点导航"生成"进入的是 **Agent 模式默认界面**，没有图片参数条（见坑 #1） |

页内常用控件（无障碍树中的名称）：模式 combobox「图片生成」、模型 combobox「图片 5.0 Lite」、参数摘要按钮（形如「2:3 2K 4」）、生成按钮（有内容时激活）、详情视图「下载」「用作参考图」按钮、缩略图条（image 元素）。

## 全流程步骤（已验证）

以下"元素"均指 `get_app_state` 返回的无障碍树条目（`[n]` 为当次 state 的 index，**每次观察后都会变**，不要复用旧 index）。

1. **打开/导航**：`open_application({bundle_id:"com.apple.Safari", url:<生成页URL>})`。Safari 未运行则冷启动，已运行则在当前窗口新开标签页导航（旧标签保留）。
2. **观察**：`get_app_state({app_ref:{pid}})`，必要时 `include_screenshot:true` 目视核对。
3. **确认创作类型**：点 combobox「图片生成」展开「创作类型」列表 → 点「图片生成」（selected 项）收起。
4. **确认模型**：点 combobox「图片 5.0 Lite」展开模型列表（5.0 Pro / 5.0 Lite / 4.7 / 4.6 / 4.5 / 4.1 / 4.0 / 3.1 / 3.0）→ 点目标模型。
5. **确认参数**：点摘要按钮（形如「2:3 2K 4」= 比例/分辨率/数量）展开面板：比例 radio 组（智能/1:1/3:4/16:9/4:3/9:16/2:3/3:2/21:9）、分辨率 radio（**高清 2K** / 超清 4K，2K 对应 1664×2496）、数量 radio（1–8）。radio 的选中态直接可读（`= 1` 即选中），点选后重观察确认。
6. **输入提示词**：点 textarea 聚焦 → `type({app_ref:{pid}, text:<prompt>})`。**不能用 set_value**（见坑 #2）。
7. **生成**：提示词非空后生成按钮从 disabled 变 pressable，点击。4 张 2K 约 30 秒出齐；完成后消息流出现图片卡片 + 「你可以试试这样改」建议，侧边栏出现以 prompt 命名的新对话。
8. **逐张下载**：点第 1 张图片卡片进入详情视图（大图 + 右侧 4 缩略图 + 「下载」按钮）→ 点「下载」→ 点缩略图 2 → 点「下载」→ 依次 3、4。每次元素写入后 state 失效，需重新观察再取新 index。
9. **验证落盘**：`ls -lt ~/Downloads | grep <关键词>`。
10. **读取**：Read 工具直接读 PNG（即梦出图为带水印位图，直接可看）；`sips -g pixelWidth -g pixelHeight <file>` 验证尺寸。

## 产物规格（实测）

- 尺寸：1664×2496（2:3 高清 2K 档）；每张约 1–1.5 MB PNG。
- 文件名格式：`jimeng-YYYY-MM-DD-NNNN-<prompt前约60字>....png`（NNNN 为 4 位随机编号，同批 4 张编号各不相同，可作区分依据）。
- **图内含"AI生成"水印**（左上角，烘在像素里）。作为参考图用不影响（转换时本来只取信息结构）；若某用途忌水印，需裁切或走其他出图通道。
- 计费：2K 档 3 积分/张（4 张 12 积分）；详情视图另有生成视频/智能超清/局部重绘等按钮，未测。

## 坑清单（症状 → 原因 → 解法）

| # | 症状 | 原因 | 解法 |
|---|---|---|---|
| 1 | 从首页点"生成"进入的界面没有图片参数条，输入框下是「Agent 模式 / 自动 / 使用技能」 | 生成页默认落在 Agent 模式界面 | 直接导航带 `?type=image` 的生成页 URL |
| 2 | 对提示词 textarea `set_value` 显示 dispatched 但值没落、生成按钮仍 disabled | React 受控组件，AX 写值不触发前端状态更新 | 点 textarea 聚焦后用 `type(app_ref)` 逐字键入 |
| 3 | 「Agent 模式 ∨」下拉触发器：AXPress 和原始坐标 event 点击都不展开 | 网页自定义组件，普通 click 不响应 | 放弃点它，走 URL 导航（坑 #1 同解） |
| 4 | 地址栏 `set_value` 后按 Return 不跳转 | set_value 不聚焦输入框，Return 打在了页面上 | 导航一律用 `open_application(bundle_id, url)`，不用地址栏 |
| 5 | 元素点击报 `state_id was superseded` | 每次元素写入后旧 state 即失效 | 重新 `get_app_state` 取新 state_id/index，绝不重放旧调用 |
| 6 | 上一步还能点的按钮这一步 index 变了 | 树随 UI 状态重排（面板开合、消息追加都会变） | 以元素**名称**（如「下载」「图片 5.0 Lite」）在新 state 里重新定位，不记 index |
| 7 | 输入框已有文字时，cmd+A 全选后直接键入新中文，开头十几个字被吞（如"基于这张角色图重新上色：保持造型、姿势、比"只剩"基比例"） | 全选替换与输入法合成窗口竞争，头部字符落在替换提交的空档 | **先 cmd+A → delete 清空，再键入**；输入后核对 textarea 开头是否完整 |
| 8 | 想让即梦参考本地下载过的图再生成，担心要走 macOS 文件上传对话框 | —— | 不需要：详情视图点「**用作参考图**」，参考图直接挂到输入框（见下节） |
| 9 | 【高危】textarea 点击返回 `mismatched` 后仍执行 app 级 `type`， keystroke 落到错误焦点层，实测导致 **Safari 所有窗口被关闭** | 点击未成功聚焦，键盘事件被系统层解释（含快捷键式副作用） | **type 前必须确认树中该 textarea 标记 `focused`**；未聚焦就重试点击再观察。type 后核对内容开头是否完整。出现毁灭性副作用时：菜单栏「退出 Safari 浏览器」优雅结束进程 → `open_application` 冷启动恢复（登录态在服务端，无损失） |
| 10 | `get_app_state` 对 web 窗口持续返回**菜单栏树**（约 1000 个 menuitem 元素、窗口标题变"Safari浏览器"）；`list_displays` 返回 `[]`；`screenshot` 报 "display no longer available" | 显示器睡眠/显示通道断裂，窗口级 AX 读取随之退化 | 唤醒显示器（`caffeinate -u -t 5` 或物理操作）后重试；若 `list_displays` 持续为空，**本次运行按异常结束**（记录原因，不回写进度表），等待定时任务下次触发自恢复——绝不盲操作 |

## 经验结论（两次运行稳定复现）

- **a11y 通路覆盖率高**：即梦的 combobox/radio/普通按钮全部可用 AXPress 可靠操作，全程无需坐标盲点；坐标 event 点击仅作为兜底（本任务中唯一需要它的场景后来也改走了 URL）。
- **观察-动作节奏**：一次观察 → 一个动作 → 需要下一步定位时再观察。`return_state:"compact"` 能在动作返回时附带新树，省一轮观察；但注意其返回的 state 同样会在下一次写入后失效。
- **截图用于核对而非定位**：`include_screenshot:true` 适合在关键节点（生成完成、切换缩略图）目视确认，定位仍以元素树为准。
- **参数选择服务端持久化**：第二次进入生成页时上次的模型/比例/分辨率/数量已保留；但正式流程仍应逐项显式点选确认（防他人改过配置，且验证控件可用）。
- **详情视图下载是逐张的**：没有"全部下载"按钮，4 张 = 切 4 次缩略图 + 点 4 次「下载」，Safari 全程免弹窗。

## 引用图再生成（img2img，已验证）

即梦支持以已有图为参考再生成，**最优通路是「用作参考图」按钮**，全程绕开 macOS 文件选择面板：

1. 打开基准图的详情视图（对话流里点该图卡片）。
2. 若基准图不是当前大图，先点缩略图条切换。
3. 点右下功能区的「**用作参考图**」→ 参考图缩略自动挂到输入框左侧（带 + 角标）。
4. 改参数（如数量 4→2：参数条显示「2:3 2K 2」），清空旧 prompt 后键入新 prompt（注意坑 #7）。
5. 生成、下载与文生图流程一致；衍生图的详情视图会出现「**智能参考**」标记。

实测用例（2026-09-04）：用《参考图生成约束》的「明暗归组版」派生 prompt 对打分选中的原图做 img2img，2 张 2K 产出与原图造型/构图一致性高（打分 8.2 / 8.8），上色明显更平、部件明暗归组清晰——信息图管线的机器通路成立。

## 参考图管线全链路（Mac 自动化，2026-09-04 三关一次通过）

```
即梦文生图(4张, 按约束模板)
  → 下载 + Read 打分（≥7.5 取最高）        ← 实测最高 8.6
  → 「用作参考图」+ 明暗归组 prompt → img2img(2张)
  → 下载 + Read 打分（≥7.5 取最高）        ← 实测最高 8.8
  → 原图 + 信息图作为规格输入，派 pixel-quick 子代理（另一会话）极速像素化
  → 32×32 快测稿，pixcli check exit 0
```

- 打分标准即《参考图生成约束》的硬性条目（白底/平涂 2–3 阶/全身完整居中/剪影特征/负面清单），由主代理 Read 目测执行。
- 两道图关若最高分 <7.5，按约束文档应换 prompt 或换模型重出，不硬凑。
- pixel-quick 派发需自包含：两张图绝对路径 + 剪影级必保特征 + 档位（如小怪 32×32）+ 产出落 `previews/quick/<资产名>/` + 门禁不放宽。
- **故障自愈（2026-09-04 实战验证）**：定时运行遇坑 #9/#10 类环境故障时，按预案记录后结束即可，不回写进度表——下次触发的全新会话会自动重选同一目标从头执行。跨会话状态只依赖进度表文件，不依赖任何会话记忆。
