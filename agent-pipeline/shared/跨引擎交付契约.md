> **效力**：与 `像素资产约定.md` 同级的共同基线。约定文件管「画什么」（画布/色数/描边/命名/目录），本文管「怎么交出去才能被引擎直接吃下」。
> **触发条件**：任何要交付给游戏工程消费的像素资产（角色帧、特效、tile）——即产出的东西需要被 Web / Unity / Godot 载入播放时，按本文验收。
> **基准唯一事实源**：项目级档位（画布尺寸、朝向集、动作清单）仍以工作区 `AGENTS.md` 为准；本文只定跨引擎不变的交付规格。

## 2. 元数据硬规格（JSON）

**交换格式：Aseprite JSON（Hash 变体）**。它是少数同时携带「帧矩形 + 每帧时长 + 动画标签」的格式，且 Unity/Godot 均有成熟导入器。

```jsonc
{
  "frames": {
    "hero_walk_00": {
      "frame": { "x": 0, "y": 0, "w": 48, "h": 48 },
      "rotated": false,
      "trimmed": false,                                  // 必须 false
      "spriteSourceSize": { "x": 0, "y": 0, "w": 48, "h": 48 },  // 必须等于 frame
      "sourceSize": { "w": 48, "h": 48 },                // 必须等于画布
      "duration": 83                                     // ms，逐帧
    }
  },
  "meta": {
    "image": "hero_walk_sheet.png",
    "format": "RGBA8888",
    "size": { "w": 480, "h": 48 },
    "scale": "1",
    "pivot": { "x": 24, "y": 47 },                      // 脚底水平中心 (w/2, h-1)，全组唯一（规则 2）
    "sourceRoute": "authored",                          // 来源路线（见下「来源路线」段）；工具链产物自动写入
    "frameTags": [ { "name": "walk", "from": 0, "to": 5, "direction": "forward" } ]
  }
}
```

**四条硬规则**：

1. **禁止 trim**：`trimmed=false`，且 `spriteSourceSize == frame == sourceSize`。Aseprite 默认会裁掉四周透明边，一旦裁剪，各帧偏移不同 → 引擎侧 pivot 漂移、角色原地抖动。这是跨引擎最常见的事故源。
2. **pivot 唯一且显式**：全组帧共用**脚底水平中心**（`x = w/2, y = h-1`），与 `pixcli check` 的「帧组脚底与水平中心对齐」同口径。JSON 里不写逐帧不同 pivot；pivot 变化只能靠「换动作组」实现。本工具链把它写在 `meta.pivot`（Aseprite 原生 JSON 无此字段，导入器多数支持覆盖），`pixcli atlas` 强制校验。
3. **画布组内恒定**：同一动作组所有帧画布尺寸一致，动作幅度变化靠透明留白吸收（攻击帧要更宽 → 该动作组整体用更宽画布，不用「帧宽不一致」）。跨动作组画布可不同，但必须在 JSON 中保持 `sourceSize` 与实际一致。
4. **时序信息进 JSON，不写死 fps**：以 `duration`(ms) 为准，引擎侧换算。循环语义由 `frameTags[].direction` 表达：`idle/walk/run` 用 `forward` + 循环；`attack/hurt/death` 用 `forward` + 不循环；呼吸/悬浮类用 `pingpong`。

**来源路线（`meta.sourceRoute`）**：`authored`（手绘 / 重绘，默认）或 `sampled`（采样像素风格，由工具从图片/视频采样量化生成）——两条路线的规格差异见 `像素资产约定.md`「资产来源路线」。未标注时按 `authored` 处理。**工具链已产出该字段**：`video-studio.html` / `pixcli video-std` 写 `sampled`，`asset-inspector` 导出 sheet 时可选，`pixcli atlas` 校验（缺失记 P2、非法值记 P1）。

**调色板随资产交付**：导出 GPL / PAL / JSON 任一格式，供引擎侧做受击闪白、染色、换皮。约定见 `像素资产约定.md` §8（运行时效果不烘进精灵）。

## 3. 三端落地路径

**关键结论：以 `.aseprite` 为源文件，Unity 和 Godot 都免写适配层；只有 Web 需要一次性的 JSON Hash 适配。**

| 引擎 | 入口 | 配置要点 |
|---|---|---|
| **Unity** | 官方包 `com.unity.2d.aseprite`（2D Aseprite Importer）直接导入 `.aseprite`/`.ase` | Import Mode = Animated Sprite（或 Sprite Sheet）；**Pivot Space = Canvas**、Pivot Alignment = Bottom（对应脚底中心）；每个 Aseprite tag → 一个 Animation Clip，速度取 Aseprite 的固定帧率；纹理 Filter = Point、Compression = None、Mip Maps = False |
| **Godot 4** | 插件 Aseprite Wizard（MIT）导入 `.aseprite` → SpriteFrames / AnimatedSprite2D | tag → 动画、`duration`(ms) → 引擎 fps、支持 loop 与 ping-pong；若走纯 PNG 路线：Import 面板 Filter = Nearest、关 Mipmaps（或项目设置 Rendering → Textures → Canvas Textures → Default Texture Filter = Nearest） |
| **Web（Phaser 4 / PixiJS）** | Phaser 4 有内置 Aseprite 载入器（`AsepriteFile` + `createFromAseprite`），可直接吃 sheet + Aseprite JSON；PixiJS / Phaser 3 走 TexturePacker **JSON Hash** | 采样必须 NEAREST、整数缩放（Pixi `SCALE_MODES.NEAREST`；Phaser `pixelArt: true`）；JSON Hash 与 Aseprite JSON 的差异用一次性转换脚本抹平（帧矩形字段名不同，语义一致） |

**适配层只写一次**：`aseprite.json → texturepacker-hash.json` 的转换器已落地——
`pixcli atlas <sheet> <json> --format hash -o <out.json>`（门禁通过才写），每个 Web 项目复用，不重复手改。

## 4. 交付门禁

### 4.1 已有（`pixcli check`，exit 0 为唯一交付门禁）

覆盖：尺寸档位、RGBA 模式、alpha 两态、唯一色数 ≤16、色板合规、帧组脚底与水平中心对齐、动画一致性（死帧/跳变/循环突断）、孤立像素、连通域。

### 4.2 sheet ↔ 元数据门禁（已全部落地）

**2026-09-08**：`pixcli atlas` 实现判据 1–3；`video-studio.html` / `pixcli video-std` 随 sheet 输出 `_sheet.json`（`meta.pivot` 齐备）。
**2026-09-09 收口**：判据 4/5 与聚合入口全部落地。

| 判据 | 命令 | 级别 |
|---|---|---|
| 1 sheet ↔ JSON 一致性（帧数 / 矩形越界 / 矩形重叠 / 逐像素需 `--frames`） | `pixcli atlas <sheet> <json>` | P0/P1 |
| 2 pivot 唯一显式 = 脚底水平中心 `(w/2, h-1)`；`trimmed=false` 且 `sourceSize == frame` | 同上 | P1 |
| 3 tags 连续、无重叠、无越界 | 同上 | P0/P1 |
| 4 采样保真：疑似整数倍放大稿 | `pixcli atlas ... --fidelity` | **P2 提示** |
| 5 调色板随资产交付 | `pixcli atlas ... --palette-out <pal.gpl｜pal.json>`（`.gpl`=GIMP，其他=本仓 JSON） | 产出 |
| 聚合入口 | `pixcli check --atlas <目录>`（并入 check 门禁链）/ `pixcli audit <目录>`（逐资产全量） | exit 1 |

**判据 4 的口径与局限**（2026-09-09）：按契约字面判据「以 NEAREST 整数倍放大后仍为纯色块」实现——存在 k ∈ 2..16 整除画布、且每个 k×k 块内颜色完全一致（即该 sheet 恰为某小图的 k× 最近邻放大）即提示。**对齐特征的原生稿与放大稿在像素上不可分**（该图本身就是合法的 k× 放大稿），故只作 P2 提示、需 `--fidelity` 显式开启、不作门禁；命中时先查源素材（AI 直出放大稿是主要来源）。

## 6. 与视频 / 图片素材的关系（两条用法）

**用法一：动作参考（authored 路线的输入）**

```
AI 视频（omni/veo）
  → 抽帧/关键姿态（参考，不进资产）
  → 重绘为像素资产（pixel-imitator 路线，或姿态驱动骨架路线）
  → pixcli check 门禁（exit 0）
  → 四件套交付（§1）
```

**用法二：采样像素风格（sampled 路线，2026-09-08 立）**

```
任意图片 / 视频
  → 采样 + 量化 + 归板（video-studio.html / asset-inspector / pixcli video-std）
  → 采样侧验收（pixcli stability 读数 + pixcli atlas 一致性；check 的手绘门禁不作否决）
  → 四件套交付（§1，meta.sourceRoute = "sampled"）
```

采样产物**可以是可交付资产**（不再一律视为「参考与预览」），前提三条：① 项目 `AGENTS.md` 允许该资产类别使用采样风格；② 按 `像素资产约定.md`「资产来源路线」的 sampled 规格执行（归板后 ≤16 色、alpha 两态、帧尺寸一致；脚底对齐 / 描边闭合 / 明暗阶次不强制）；③ 交付时声明路线。

旧口径「视频产物只作参考」自本日起仅适用于**未按 sampled 规格处理的中间产物**（纯抽帧、未归板的 GIF/sheet 等）。
